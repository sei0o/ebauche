
## 背景・課題

模写はしたいのに、迷う・時間がかかる・細部に入り込むせいで避けてしまうのが中心の課題。

- 何を描くか迷う、時間がかかる、準備が面倒で避けがち
- 細部に入り込んでしまう
- ブクマした絵の何が良かったかを忘れる、忘れるので模写する気がしない
- イラストの模写は線画がすごくてハードルが高い
- 既存手法の課題：Scrapboxはモバイルから書きにくい、SNSは既存の写真を上げられない、つい見てしまい、上手い人と比べてやる気が落ちる

## 基本方針

- 30deskの良いところ（画像を選ばなくていい・時間で終わる・すぐ始められる）を自分向けにする
- 自分専用・非公開

## 資料の保存

スマホから直アップし、保存時に「なぜ良いか」を残す

- スマホから直アップ（複数枚まとめて）。iPhoneならショートカット経由も可
- 種類：写真 / イラスト（別の棚）
- 保存時に固定の選択肢から1〜2タップ
- メモ：何がよいと思ったか？描けそうか or むりそうか？
    - フリーテキストでもタグでも
        - Danbooruとかも参考にできるかもな
        - 描かれている対象と、描いている手法
- とりあえずまずはここから実装する。写真見て白黒にしたりしてうおーってなろう。そうするとデータが溜まっていくはず。

## 模写練習

- ランダムに1枚。引き直しは1~2回まで
- 時間を選ぶ：5 or 30分
- タグに応じて制限を自動で出す（例：光 → ノタン、構図 → サムネイル、線 → 一部を切り抜き）

細部対策に特に効きそうなのは、ストローク数の上限・遠目表示・記憶模写・段階解禁の4つ。

|種類|制限|
|---|---|
|明暗|バリュースケッチ2〜4段階、ノタン、中間グレーの紙から、暗い背景から|
|形|シルエットのみ、投げ縄で塗るだけ、直線だけ、ネガティブスペース|
|線|ストローク数の上限、ブラインドコンター、消しゴム・Undoなし、筆圧オフ|
|色|資料から抜いた5色のみ、色相は固定、色の塊だけ|
|時間|ジェスチャー連続、同じ画像を1→5→15分、段階解禁|
|資料の見せ方|記憶模写、上下逆さま、ちら見だけ、一部を切り抜き、ぼかし→だんだんくっきり|
|キャンバス|ときどき強制的に遠目表示、小さいサイズで固定|

## キャンバス（自作、HTML canvas）

ズームなし・ブラシ少なめ・小さいサイズ固定で、細部に行かせないキャンバスにする。

- Pointer Eventsで筆圧を取る。ペンだけ反応させて誤タッチを防ぐ
- ブラシは少なく（3〜4種類）
    - ブラシってどうやってつくるんだろ
- ズーム禁止（`touch-action: none` と `gesturestart` の抑止）
- はがきくらいの小さいサイズで固定、ブラシの最小サイズは太め
- 時間とともに細いブラシが解禁される
- レイヤーは自分用に固定（例：下塗り・影・線）、または1枚だけ
- 消しゴムは `destination-out`、Undoはストローク単位のスナップショット
- 保存はPNGでRailsへ
- ストロークのログ（時刻・位置・サイズ・筆圧）を記録する
- クリスタなどで描きたい場合は、iPadのSplit Viewで並べて、書き出した画像をアップする

## 振り返り

時間切れ後に元絵と並べ、光の「配置」と明暗・彩度の分布を答え合わせする。

- 時間切れ後、自分の絵と元絵を並べる
- 上からペンで書き込める手書きメモ（青ペンのように）
- 明暗3段階・2値の比較にワンタップで切り替え → 光の「配置」の答え合わせ
- HSVヒストグラム → 明暗の幅・彩度の「量」の答え合わせ（ただし位置の情報は消える）
- 最後に資料を半透明で重ねて、ずれを見る
- カレンダー・連続日数、同じ資料に時期を変えて再挑戦
- 振り返りのメモを次のお題に反映（例：「光がわからん」→ 次回はノタン3分 → カラー）

## 分析（ML・粗視化の視点）

MLは描く側ではなく、評価と分析に使う。

- **マルチスケールの答え合わせ**：ぼかし幅ごとに一致度を出す。粗いスケールから合っているか
- **ストロークのログ**：ブラシサイズを時間に対してプロットし、粗→細の順で描けているかを見る
- **2次元マップ**
    - 特徴量はCLIP（内容）、DINOv2（構造）、Gram行列（絵柄・質感）、手作り（明暗・彩度・配置）
    - マップを切り替えて見られるようにする
    - 配置は学習済みの埋め込み、解釈は手作りの特徴量で色分けや相関を見る
    - 模写→元絵の矢印で自分の癖を見る（例：明暗の幅が狭い・彩度が低い）
    - タグで色分けして、自分が惹かれるものの地図にする
- **タグの集計画面**：自分が何に惹かれるか（絵柄の種）

## 技術構成

Railsは保存と表示、分析はPythonスクリプトという分担にする。

- Rails：`Ref`（画像・種類・タグ・メモ）、`Study`（資料・時間・制限・描いた絵・ストロークログ・日付）
- Active Storage、加工はCSSの `filter` か `image_processing`（libvips）
- 分析はPythonスクリプトで特徴量と2次元座標を計算 → DBに書き込み → Railsで散布図表示
    - 他の方法でもよい
- Flaskのほうがいいかもなあ。考え中

## 進める順番

まずキャンバスだけ試作し、描き心地を確かめてからRailsに載せる。

1. キャンバスだけHTML 1枚で試作（ズームなし・ブラシ少なめ・段階タイマー）、iPadで描き心地を確かめる
2. Railsに載せる：直アップ＋タグ、ランダム出題＋タイマー＋モノクロ切り替え、描いた絵の保存
3. 振り返り画面（並べる・書き込み・明暗比較）
4. 制限のランダム出題
5. 画像がたまったら分析（マップ・ヒストグラム・ストロークログ）
